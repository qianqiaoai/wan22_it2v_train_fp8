# Experiment Record: avsync_sampling

Time: 2026-06-20 01:54:35 UTC

## Goal

Sample real training clips to inspect whether the current 20fps resampling and matching audio crop are visually/audio synchronized.

## Code/Config Changes

- No repository training code or config was changed.
- A temporary helper script was created at `/tmp/sample_av_sync.py`.

## Sampling Method

The generated `train20fps_avsync.mp4` files mimic the current training data path:

- Read source video with `decord`.
- Resample video to `20fps` using the same timestamp/round-index style as `dataset.py`.
- Select an `81`-frame crop from the 20fps sequence.
- Cut audio from the separate `audio_path` at `frame_start / 20fps` for `81 / 20 = 4.05s`.
- Resize/center-crop frames to `832x480`.
- Mux the selected frames and audio into mp4.

For comparison, each sample also has a `sourcefps_avsync.mp4` file:

- Same start time and duration.
- Source video sampled at its original fps.
- Same cropped audio segment.
- Same resize/center-crop.

## Manual Check Needed

Open each `train20fps_avsync.mp4` and its matching `sourcefps_avsync.mp4` side by side:

- If both are similarly off-sync, the issue is likely source audio/video offset or dataset quality.
- If source-fps is synced but train20fps is visibly worse, the 20fps resampling/cropping path is likely causing or amplifying lip-sync error.
- If only some rows are bad, inspect the manifest `lipsync`, `LSE_C`, `LSE_D`, and row paths for dataset filtering issues.
